## 0. 작업 방식

- 코드는 **바뀐 부분만** 제시합니다. 파일 전체를 다시 쓰지 않습니다.
- 디버깅은 **분석 먼저**. 원인을 설명하고 합의한 뒤 코딩합니다.
- DB 변경은 `supabase/migration_00N_*.sql` 새 파일로. `schema.sql`은 최초 설치본으로 두고 고치지 않습니다.
- 화면 문구는 한국어 해요체.

### 보안 원칙

- 브라우저와 GitHub Variables에는 **publishable key만**. secret / service_role key는 로컬 업로드 폴더의 `.env`에만 둡니다.
- 권한은 화면에서 숨기는 게 아니라 **RLS + SECURITY DEFINER RPC**로 막습니다.
- 저장소는 public이므로 원본 데이터(`column_backup_data`)는 git 저장소 밖 폴더에 둡니다.

## 3. 콘텐츠 규칙

### 칼럼 (.md)
- ID = 네이버 콘텐츠 ID (`source_url`의 `/contents/<ID>`)
- 저장: `columns/md/<ID>.md`, 이미지 `columns/images/<name>` (md에서 참조된 것만)
- 날짜: 프런트매터 → 본문 `viewer_date_text` → 콘텐츠 ID 앞 12자리(YYMMDDHHMMSS) 순서
- 본문이 "본문 내용을 불러오지 못했습니다"인 파일은 업로드하지 않음 (다운로더 메뉴 4로 복구)

### 소설 (.txt, 1편 = 1파일)
- 회차 나누기 판단 순서 (inspect_novels.py `split_any` / `plan_novel`, upload.py 공용)
  1. `=====` / 제목 / `=====` 3줄 블록. 제목 과반이 `[`로 시작하면 `[`로 시작하지 않는 블록은 본문(상태창)
  2. **번호 줄기 (여러 형식 혼합)**: 아래 형식을 모두 후보로 모아, 번호가 차례로 늘어나는 가장 긴 줄기를 회차 제목으로
     - `N화 제목`·`제N화`, `N. 제목`, `N 제목`(숫자+공백+짧은 제목), `작품명 N화`(+ 다음 줄이 제목, 같은 앞부분 3번 이상), `< 제목 >` + 아래 `#N`, `EP.N`
     - 앞 줄이 빈 줄·구분선이어야 함, 40자 이하, 마침표로 끝나는 문장은 제외
     - 한 번에 5 이하로 늘거나, 그 사이 글 양으로 말이 되는 만큼(2,500자당 1화) 건너뛸 수 있음
     - `N. 제목`·`N 제목`은 같은 형식이 3개 넘게 이어지거나 앞뒤 번호와 딱 맞물릴 때만 (본문 속 번호 목록 배제)
     - 같은 번호·같은 제목이 연달아 나오면 중복 회차 → 뒤의 것(다음 회차 제목까지)은 버리고 경고
  3. **번호 빈 구간 채우기**: 앞부분(첫 번호가 1이 아님) · 중간(번호가 비고 덩어리가 평균의 1.5배 이상) · 끝(마지막 회차가 평균의 2.5배 이상)
     - 후보: 번호 없는 `< 제목 >` 줄, **제목만 있는 줄**(앞뒤 빈 줄, 25자 이하, 따옴표·기호로 시작 안 함, 문장부호로 안 끝남 / `~다` 문장·효과음은 감점, 같은 제목 연속·`(N)` 은 가점)
     - 회차 크기가 고르게 되도록 동적 계획법으로 고름 (본문 속 짧은 줄은 대부분 걸러짐)
     - 번호: 빈 칸 수와 딱 맞으면 그대로, 아니면 **크기로 보정**(평균 2배 덩어리는 2칸 차지) → 목록에 `≈` 표시
     - 제목만 있는 줄은 **본문에서 지우지 않음** (잘못 고른 본문 줄이어도 글이 사라지지 않게)
  4. 엔딩 뒤 `후기`·`작가의 말` 제목 줄 → 번호 없는 "후기" 회차(`x0001`)
  5. 번호 줄기가 없으면 `< 제목 >` 줄 (평균 회차가 3만 자 넘게 드물면 본문 속 표시로 보고 안 씀) → 제목만 있는 줄(간격 2,500~15,000자로 고를 때만) → 크기 분할
  6. 크기 분할: 5,000자(웹소설 1화 ≈ 공백 포함 5천 자, `--chunk` 로 변경) 넘긴 뒤 자름
     - 장면 전환 기호 줄(`***`, `---`, `* * *`, `◆◇◆` 등 기호만 3개 이상, 앞뒤 빈 줄) 우선 — 4,250자부터 가능, 그 줄은 버림
     - 같은 모양 기호 줄이 30줄 안에서 짝을 이루면 상태창 테두리로 보고 자르지 않으며, 그 안쪽 빈 줄에서도 안 자름 (7,500자 넘으면 예외)
     - 제목: `1편 · 첫 문장 앞 20자…`
- 모든 방식 공통: 본문 첫 줄이 회차 제목과 같으면 지움 (위 바 제목과 중복 방지)
- 첫 회차 앞 내용(소개글·서장 등)은 `프롤로그` 회차(키 `intro`)로
- 회차 번호: `[EP.n]` → 앞의 `n화` → 끝의 `n화` 순서로 찾음
- 작가 이름은 파일에서 뽑지 않고 관리 탭에서 직접 입력
- 회차 키: `n0033`(회차 번호, 번호 줄기·보정 포함) / `s0012`(등장 순서) / `p0003`(크기 분할) / `x0001`(번호 없는 꼬리: BONUS·후기) / `intro`
- 표시 제목: 번호 줄기는 `N화 제목` 으로 통일(`841. 제목` → `841화 제목`, `당문전 201화`+`참회동` → `201화 참회동`) → 웹 목록은 번호 칸 + 제목
- 표시 제목: `[작품명]`과 뒤의 `-`, `:` 제거
- **상식 검사 → 보류**: 프롤로그가 2만 자(또는 중앙값 3배) 넘음 / 회차 하나가 3만 자이면서 중앙값 4배 넘음 / 평균 회차 2만 자 넘음 / 회차 키 중복
  - 보류된 소설은 올리지 않고 건너뜀, 회차 제목일 수 있는 줄(줄 번호 + 앞뒤 줄)을 보여 주고, 끝에 건너뛴 목록을 한 번 더
  - `--force "이름"`: 그대로 올림 (이름 없이 `--force` = 전부) / `--split "이름=size"` 또는 `"이름=size:8000"`: 회차 제목 무시하고 글자 수로
  - inspect_novels.py 도 같은 검사, 표에 `판정`(OK/✖ 보류), 상세에 `혼합: 제목줄→N. 제목→N 제목→작품명 N화→N화` 처럼 형식이 바뀐 순서
- 업로드 시 순서 키 소설의 중간 삽입이 감지되면 멈춤 → `--force "이름"`
- 소설 ID는 `novels_map.json` (현재 `nv-xxxxxxxx` 자동 ID로 확정). 소설 구분은 **파일 이름** 기준 (이름을 바꾸면 새 소설 → 작가·장르·태그 없음)
- 다시 올리기: `upload.py --replace "이름"` → 그 소설의 회차 행·회차 파일을 지우고 전부 새로 (y 확인, `--dry-run` 미리 보기, `--yes` 질문 생략). 소설 ID·작가·장르·태그 유지
- 전체 다시 올리기: `upload.py --replace-all` → **보류되지 않은** 소설의 회차·회차 파일을 지우고 전부 새로. `"모두 지움"` 직접 입력, 보류된 소설은 손대지 않음, 폴더에 파일이 없는 소설은 따로 물어보고 삭제. 칼럼·소설 ID·작가·장르·태그 유지
- 다시 올릴 때 읽기 기록: **회차 키와 내용(해시)이 그대로인 회차의 기록만 남기고** 나머지는 지움 (번호가 정확한 회차는 다시 올려도 읽음·읽던 위치 유지)
- 소설 지우기: `upload.py --delete "이름"` → 소설·회차 목록·회차 파일·표지·작가·장르·태그·**모든 사용자의 그 소설 읽기 기록** 삭제
  - 이름은 파일 이름(확장자·`novels/` 경로 있어도 됨) · 제목 · ID, 여러 번 지정 가능. `y` 확인(`--yes` 생략), `--dry-run` 미리 보기, 삭제만 하고 끝남
  - 폴더에 txt가 남아 있으면 다음 업로드 때 다시 올라감 → 빼 두라고 안내. `novels_map.json` ID는 유지

## 4. 결정된 화면 정책

### 읽기 기록 (계정별, 서버 `reading_state`)
- 읽던 위치: 칼럼은 마지막 문단 id(`SE-...`), 소설은 `회차키:줄번호`
- 저장 시점: 스크롤이 멈추고 몇 초 뒤 + 화면을 벗어날 때
- 기기 간 동기화, 충돌 시 더 최근 기록 우선
- 오프라인에서 읽은 기록은 기기에 모았다가 연결되면 전송 (outbox)
- **읽음 처리는 자동 + 수동 둘 다**
  - 마지막 문단이 화면에 들어오면 자동으로 읽음 (화면보다 짧은 글은 열면 바로)
  - 하단 버튼으로 "다 읽음" ↔ "안 읽음으로" 전환
  - 안 읽음으로 돌린 글은 다음에 끝까지 읽으면 다시 자동 읽음
- 소설 "새 회차": 그 소설을 마지막으로 연 이후 추가된 회차

### 보기 설정 (기기별, localStorage)
- 칼럼·소설 읽기 화면의 ⚙ 버튼 (v2.3부터 가운데 위의 작은 창, 아래 "읽기 화면 v3" 참고)
- 기본은 칼럼·소설 **따로** 저장 (기본값이 서로 달라서). 고급 설정의 **"칼럼·소설 따로 설정"** 스위치를 끄면 지금 화면 설정으로 공유 시작
- 앱 전체 설정은 별도: **내 정보 → 화면 설정** = 앱 글꼴(기본: 기기 기본 고딕) + "본문 글꼴과 같게" 스위치, 앱 글자 크기(작게/보통/크게), 화면 모드(밝게/어둡게/기기 설정 따름)
- **기본**
  - 글자 크기: 14~30, 1단위
  - 줄 간격: 1.4~2.4, 0.1단위 (− / + 버튼)
  - 글꼴: 기기 기본 / 명조(본명조, 나눔명조, 고운바탕, 함렛) / 고딕(프리텐다드, 본고딕, 나눔고딕, 고운돋움)
    - 선택한 글꼴만 그때 받아오고 기기에 캐시. 다른 무료 글꼴은 웹 사용 라이선스 확인 후 추가
  - 여백: 모바일 12~40px / PC 본문 폭 560~860px (기본 700) (− / + 버튼)
  - 색: 기본 테마(밝게·종이·세피아·어둡게·검정) + **사용자 지정**(배경색·글자색 직접 선택)
    - 대비 4.5:1 미만이면 경고만 표시 (막지 않음)
    - 내 테마 최대 3개 저장
    - 상단바·하단바·설정 창 색은 배경 밝기에 맞춰 자동
    - 칼럼 원문 강조색은 고른 배경에서 읽히도록 자동 보정
- **고급 설정 (접힘)**: 문단 간격, 정렬(왼쪽/양쪽), 들여쓰기(켜기/끄기), 자간(좁게/보통/넓게)
- 칼럼 원문 글자 크기 클래스는 본문 크기에 비례(em)하도록 변환 → 글자 크기와 함께 커짐
  - 네이버 원문 기본: `.se-fs-` = 15px (768px 이상), 글꼴 나눔고딕 (`se-nanumgothic`)
  - 칼럼 271편에서 쓰인 크기: fs19(1,262) · fs16(1,196) · fs13(849) · fs24(3). 지정 글꼴(`se-ff-xxx`)은 없음
  - 변환: `se-fs-`·fs16 → 1em(본문으로 통일), fs19 → 1.25em, fs24 → 1.5em, fs13 → 0.875em
- 기본값: 칼럼 = 나눔고딕 16 · 줄 간격 1.8 / 소설 = 본명조 18 · 줄 간격 1.8 (첫 실행 시, 이후 사용자 설정)

### 넘기기 · 조작
- 기본은 스크롤 방식 (마우스 휠 그대로)
- **PC 키보드**: `↓`/`↑` 조금씩, `Space`·`PageDown`·`→` 한 화면 아래(위아래 두 줄 겹침), `Shift+Space`·`PageUp`·`←` 한 화면 위,
  회차 끝에서 `→`/`Space` 한 번 더 → 다음 회차, `Home`/`End` 처음/끝, `Esc` 설정 닫기
- **휴대폰 탭으로 넘기기**: 아래(오른쪽) 탭 = 한 화면 아래, 위(왼쪽) 탭 = 한 화면 위, 가운데 탭 = 메뉴 표시/숨김. 설정에서 켜고 끄기
- **자동 스크롤**: 속도 조절, 탭하면 멈춤
- 블루투스 페이지 넘김 리모컨은 키보드 신호(`PageDown`/`→`/`Space`)를 보내는 제품이면 그대로 동작
- 휴대폰 **볼륨키는 지원 불가**: 브라우저가 웹페이지에 전달하지 않음 (네이티브 앱에서만 가능, 채택 안 함)

### 칼럼 본문 렌더링
- 네이버 뷰어 머리글(`.se-documentTitle`)과 하단(`.viewer_bottom_section`)은 숨김
- 자기 글 링크(`/contents/<ID>`)가 서재에 있으면 서재 링크(`#/c/<ID>`)로, 없으면 원문 새 창
- `naver.me` 단축 링크는 업로드 시 실제 주소로 펼쳐 캐시

- 면책 고지 등 원문 문단은 그대로 표시

- 아래 바: `‹ 이전화` · 📌 고정 · 🔍 검색 · `42%` · `다음화 ›`, 위 테두리에 얇은 진행선
- 바는 **가운데 탭으로만** 보임/숨김 (스크롤로는 안 나옴). 목록에서 들어오면 1.5초만 보였다 숨김, 회차·글끼리 넘어갈 때는 숨긴 채. 고정 켜면 항상 보임 (PC 기본 고정)

- `%` → 위치 패널: 게이지 + 숫자 입력. 터치 기기는 앱 안 숫자 패드(휴대폰 키보드 안 띄움), PC 는 입력칸 + Enter. 바로가기 10/25/50/75/90%
  - 소설은 `% | 회차` 전환 → 회차 번호로 이동, 없는 번호는 가장 가까운 회차 안내, 바로가기 첫 화/최신 화
  - 패널 바깥을 누르면 닫히고 그 탭으로는 페이지가 넘어가지 않음
- 자동 재생: ▶ → 속도 창(1~10, 마지막 값 기억) → 시작. 재생 중 ▶ 자리가 ■ (누르면 완전히 끔)
  - 화면을 누르거나 휠 → 잠깐 멈춤 + 바 표시 + 알약 `[− 속도 +] [이어서]`. 가운데를 다시 누르거나 이어서 → 재생
  - 소설: 회차 끝에 닿으면 끝 카드에 "3초 뒤 다음 화" → 다음 화에서도 계속 재생. 마지막 화에서 꺼짐 / 칼럼: 글 끝에서 꺼짐
  - 자동 재생 중엔 항상 화면 켜짐 유지(Wake Lock)
- 본문 끝: `— 12화 끝 —` + 다음 화 카드(번호·제목) / 칼럼은 다음 글 카드
- 회차 번호: 제목에 번호가 있던 소설(키 `n0012`)은 그 번호, 번호 없는 소설(키 `s`·`p`)은 프롤로그를 뺀 등장 순서(seq), 프롤로그·끝의 번호 없는 회차(`x`)는 번호 없음. "총 N화"는 프롤로그 제외
  - 회차 목록·패널은 왼쪽 번호 칸 + 제목 (제목 앞의 `12화.`·`12편 ·` 는 겹치니 뗌)
- 보기 설정: 화면 가운데보다 조금 위의 작은 창, 뒤 배경은 어둡게 하지 않음(바꾼 게 바로 보이게), 탭 두 개(마지막 탭 기억)
  - 일반: 글꼴(목록에서 `가나다 Aa 123` 예문으로 미리보기 — 예문 글자만 담은 작은 글꼴 조각을 받음) · 테마 + 내 색(배경·글자·저장·저장한 색 1~3) · 글자 크기 · 두께 · 줄 간격 · 좌우 여백(PC 본문 폭) · 문단 간격
  - 고급: 읽을 때 전체 화면 · 읽는 동안 화면 켜두기 · 정렬(왼쪽/양쪽) · 자간 · 첫 줄 들여쓰기 · 칼럼·소설 따로 · 화면 위·아래 눌러 넘기기(PC 는 단축키 안내) · 기본값으로
  - 항목을 바꿔도 창 스크롤 위치·포커스 유지 (예전엔 맨 위로 튐)
- 읽는 동안 화면 켜두기: 칼럼·소설 공통, 기본 끔, 다른 앱 다녀오면 다시 켬, 목록으로 나가면 풂 (`src/lib/wakeLock.js`)

  - "전체 화면을 종료하려면…" 안내는 크롬이 띄우는 것이라 앱에서 줄일 수 없음

- upload.py 가 소설마다 확인 → 원본 이미지 해시(앞 16자)가 DB `cover_hash` 와 다르면 480×720 안으로 줄여 webp(품질 82)로 `novels/<id>/cover-<해시>.webp` 에 올리고 `cover_path`·`cover_hash` 갱신, 옛 표지 파일은 지움
  - txt 가 바뀌지 않아도(변경 없음) 표지만 새로 올라감. 폴더에서 이미지를 빼도 올라간 표지는 그대로
  - Pillow 필요: `pip install pillow` (없으면 표지만 건너뛰고 안내). 004 전이면 표지 건너뛰고 안내
  - `--replace`·`--replace-all` 은 표지 파일을 지우지 않음
- 웹: 서명 주소를 7일짜리로 받아 기기에 기억(`cover:urls`). 서비스 워커가 토큰을 빼고 저장 → 한 번 본 표지는 오프라인에서도. 표지가 바뀌면 파일 이름(해시)이 바뀌어 새로 받음
- 표지가 없으면 제목으로 색을 정한 기본 표지(제목·작가 글자)
- 소설 목록은 **바둑판형**: 2:3 표지(모바일 2열, PC 자동 4~6열) + 제목(2줄) · 작가 · 회차 수 · 진행률 + 장르 칩 전부 + 태그 3개(+n) + 이어 읽기. 새 회차는 표지 위 배지, 읽은 만큼 표지 아래 얇은 막대
- 소설 상세 위에 큰 표지 + 작가 · 장르 칩(누르면 그 장르 목록) · 태그 · 회차 수

### 홈 · 소설 탭 · 칼럼 탭 (v2.6)
- **홈 이어 읽기**
  - 소설: 읽던 소설을 최근 읽은 순으로 가로 한 줄(표지 96px, PC 120px). 다 읽은 회차면 "N화부터"(다음 화 처음), 아니면 "N화 · 42%"(읽던 위치). 마지막 화까지 다 읽은 소설은 빼고, 새 회차가 올라오면 다음 화가 생겨 다시 나옴(+ "새 N" 배지)
  - 회차 목록 전체를 받지 않고 회차 한두 줄만 물어봄(`src/lib/continue.js`), 결과는 기기에 기억(`cache:cont`, 기록·새 회차가 바뀌면 다시)
  - 칼럼: 읽는 중인 글을 최근 순으로 최대 5개(제목 · 분류 · 진행률). "전체 ›" → 각 탭이 "읽는 중"으로 열림(`#/novels?status=reading`, `#/columns?f=reading`)
- **소설 탭**
  - 보기 3종(위 오른쪽 전환, 기기별 기억 `ui:nvView`): 카드(기본, 휴대폰 2열 · 600px~ 3열 · 840px~ 4열 · PC 자동) / 작은 카드(표지 + 제목, 3열 · 5열 · PC 자동) / 리스트(작은 표지 + 제목 · 작가 · 장르 · 회차 수 · 진행률 · 태그 + ▶ 이어 읽기, PC 2열)
  - 열 수는 화면 폭으로 고정 (S25+ 처럼 CSS 폭 384px 에서 자동 계산이 1열로 떨어지던 문제)
  - 검색 한 칸: 제목 · 작가 · 장르 · 태그. 띄어쓰기·쉼표로 나눈 단어가 모두 맞아야 함, `#단어` 는 태그에서만, 공백·대소문자 무시
  - [필터] 창(휴대폰 아래에서, PC 가운데 위): 읽기 상태(전체/읽는 중/안 읽음/다 읽음/새 회차 있음) · 정렬(최근 읽은 순(기본)/최근 추가 순/제목 순/회차 많은 순) · 장르 · 태그(12개 넘으면 태그 찾기 칸). 바로 반영, [N편 보기] 로 닫기, [초기화]
  - 위에는 고른 조건만 칩으로(× 로 빼기) + 결과 수 + 조건 지우기. 필터 버튼에 조건 개수
  - "다 읽음" = 프롤로그를 뺀 다 읽은 회차 수 ≥ 회차 수, "새 회차 있음" = 마지막으로 연 뒤 회차가 추가됨
- **맨 위 · 맨 아래 바로 가기** (소설 목록 · 회차 목록): 스크롤하면 오른쪽 아래(하단 탭 위)에 ↑ ↓, 2초 멈추면 사라짐. 회차 목록은 가운데에 "읽던 회차" 버튼도. 화면보다 1.6배 넘게 길 때만
- **표지 크게 보기**: 소설 상세에서 표지를 누르면 어두운 배경에 화면에 맞춰 띄움(확대·축소 없음). `cover_large_path`(migration_006, 업로더가 올림 — `docs/COVER_LARGE_SPEC.md`)가 있으면 그것, 없으면 목록용 표지. 누르거나 Esc 로 닫힘
- **칼럼 탭**: 분류 칩 줄 → 분류 선택 상자(`분류 · 전체 271` / `투자 전략 34` …, 휴대폰은 기기 기본 선택 창). 읽기 상태(전체/안 읽음/읽는 중/읽음)와 정렬은 지금처럼 바깥 한 줄

### 반응형
- ~767px: 모바일 시안 그대로 (하단 탭바)
- 768~1023px: 같은 구조, 가운데 정렬 + 최대 폭
- 1024px~: 왼쪽 사이드바, 칼럼은 목록+본문 2단, 소설 회차 목록은 접이식 패널, 본문 폭 최대 680~720px
- 단축키는 "넘기기 · 조작" 참고
- **배치는 창 폭 기준**: PC에서 창을 줄이면 그대로 모바일 배치로 전환. 읽던 위치는 문단 기준이라 전환돼도 유지
- **조작은 입력 방식 기준** (폭과 무관)
  - 탭으로 넘기기: 터치 화면(`pointer: coarse`)에서만 동작. 마우스 사용 중이면 창이 좁아도 꺼짐
  - 키보드 단축키: 창 폭과 무관하게 항상 동작
  - hover 효과: 마우스(`hover: hover`)일 때만
- 보기 설정의 **여백(모바일)**과 **본문 폭(PC)**은 따로 저장. 글자 크기·글꼴·색 등 나머지는 폭과 무관하게 공유
- `J`/`K` 다음·이전 칼럼 (2단계에서 구현, 목록의 현재 대구분·검색 조건 순서를 따름). 필요 없으면 빼기 쉬움

### 하단 탭 (권한 기반)
| 사용자 | 탭 |
|---|---|
| 칼럼만 / 소설만 | 홈 · (해당 섹터) · 내 정보 — 홈의 "내 서재"는 카드 하나를 넓게 |
| 둘 다 | 홈 · 칼럼 · 소설 · 내 정보 |
| 관리자 | 홈 · 칼럼 · 소설 · 내 정보 · 관리 (대기 배지) |
| 승인됐지만 권한 0개 | 홈 · 내 정보 — "아직 열람 권한이 없어요" |
- 이어 읽기 · 최근 칼럼도 권한 있는 섹터 것만

### 관리자 화면
- 사용자 검색(이름·이메일, 화면에서 즉시 필터) + 상태 필터(전체/대기/이용 중/차단)
- 승인된 사용자도 ⋯ 메뉴로 차단 (확인 창). 차단 해제 시 기존 권한 그대로 복구 (grants 유지)
- 관리자 본인 차단 방지: RPC 확인 추가 마이그레이션 필요
- 차단된 사용자가 앱을 열면 상태 확인 후 기기 캐시·읽기 기록 삭제 (계속 오프라인인 기기는 한계)

### 기타
- 검색: 칼럼 제목·태그 (클라이언트), 본문 검색은 나중
- 오프라인: 연 글은 기기 캐시, 소설은 다음 1회차만 미리 받기
- 관리 탭에 승인 대기 배지 (이메일 알림 없음)
- PWA 설치: Chrome 설치 창 + iPhone은 Safari "홈 화면에 추가" 안내, 새 버전 배너
