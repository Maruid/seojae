## 1. 무엇을 만드는가

- **용도**: 구독 칼럼(네이버 프리미엄 "자산제곱" `.md`)과 소설(`.txt` · `.epub` · 회차 파일 폴더)을 읽는 개인용 사이트
- **사용자**: 본인과 구독 친구들. Google 로그인 → 관리자가 승인 → 섹터별(칼럼/소설) 권한 부여
- **호스팅**: GitHub Pages (공개 저장소 `Maruid/seojae`, https://maruid.github.io/seojae/)
- **백엔드**: Supabase (ref `dnihkxmecdyuplzvuemu`, 서울). DB(RLS + SECURITY DEFINER RPC), 비공개 Storage 버킷 `content`
- **콘텐츠 올리기**: 내 PC의 `seojae-sync` 폴더에서 `upload.py` 실행 (service role 키는 그 폴더의 `.env`에만 보관)

## 3. 단계별로 만든 것

### 1~4단계 (기본)
- 1단계 뼈대: Google 로그인, 승인 대기, 하단 탭(권한 기반), 화면 모드
- 2단계 칼럼: 목록(대구분·안 읽음/읽는 중/읽음·검색·월별), 읽기(본문 렌더링·이미지 서명 주소·링크 카드·임베드 카드), 읽음 처리, 서재 안 링크
- 3단계 소설: 목록, 회차 목록, 회차 읽기, 다음 회차 미리 받기, 새 회차 표시
- 4단계 관리자 + PWA: 사용자 승인·차단·섹터 권한, 통계, 서비스 워커(앱 셸·글꼴·본문 캐시), 업데이트 배너, 설치 화면, 안드로이드 하단 바 색

### 읽기 기록 (계정별, 서버)
- 칼럼은 마지막 문단 id, 소설은 회차 키 + 줄 번호 + 진행률. 기기에 먼저 저장했다가 서버로 보냄(오프라인 대비)
- 이어 읽기, 읽음 자동 처리, 목록의 진행 표시

### 읽기 화면 (v2 → v3)
- **위 바**: `<` · 제목 두 줄(작은 줄 `작품명 · 12화 / 총 120화`, 누르면 정보 팝업) · ☰ 회차 목록 · ▶ 자동 재생 · ⚙ 보기 설정
- **아래 바**: `‹ 이전화` · 📌 고정 · 🔍 검색 · `%` · `다음화 ›`, 반투명 + 흐림
- **바 동작**: 가운데 탭으로만 보임/숨김, 목록에서 들어오면 1.5초 보였다 숨김, 고정하면 항상 보임(PC 기본 고정). 스크롤할 때 화면 맨 아래 얇은 진행선이 잠깐 보임
- **넘기기**: 미끄러짐 없이 즉시, 줄 단위로 맞춰 한 줄만 겹침. 화면 위·아래 탭, Space·PageDown·←→, J·K(다음·이전 글), `/`(검색)
- **위치 패널(%)**: 게이지 + 숫자 입력. 휴대폰은 앱 안 숫자 패드(키보드가 화면을 가리지 않게), 소설은 `% | 회차` 전환으로 회차 번호 이동
- **자동 재생**: 속도 창 → 시작. 화면을 누르면 잠깐 멈춤(속도 조절 알약), ■로 끄기. 소설은 회차 끝에서 "3초 뒤 다음 화"로 계속, 칼럼은 끝에서 멈춤. 재생 중 화면 켜짐 유지
- **본문 끝**: `— 12화 끝 —` + 다음 화(칼럼은 다음 글) 카드
- **검색**: 지금 보는 글 안에서, 결과 이동
- **전체 화면**(안드로이드·PC): 카메라 구멍 자리를 검은 띠로 가리고 그 아래부터 읽기
- 터치 기기에서 두 번 탭해도 글자 선택·구글 검색 창이 뜨지 않게 함

### 보기 설정 (기기별)
- 화면 가운데 위의 작은 창, 뒤 배경은 어둡게 하지 않음(바꾼 게 바로 보이게), 바꿔도 깜빡이지 않고 스크롤 유지
- 일반 탭: 글꼴(`가나다 Aa 123` 미리보기 목록) · 테마(자동/밝게/종이/세피아/어둡게/검정 + 내 색 바로 편집·저장 3개) · 글자 크기 · 두께 · 줄 간격 · 좌우 여백(PC 본문 폭) · 문단 간격
- 고급 탭: 읽을 때 전체 화면 · 읽는 동안 화면 켜두기 · 정렬(왼쪽/양쪽) · 자간 · 첫 줄 들여쓰기 · 칼럼·소설 따로 · 화면 위·아래 눌러 넘기기 · 기본값으로

### 소설 목록 · 메타 (v2.5)
- **표지**: 소설과 같은 이름의 이미지(`당문전.jpg`)를 두면 upload.py가 자동으로 올림 (폴더는 안의 `cover.*`, epub 은 안의 표지도). 없으면 제목 색으로 만든 기본 표지
- **장르 여러 개 + 태그**: 관리 › 소설 정보에서 칩으로 입력(쉼표·탭·줄바꿈·`/`로 나눔, 태그는 `#` 자동, 태그 안 공백 제거). `upload.py --meta` 로 한꺼번에도 가능
- 소설 상세 위에 큰 표지 + 작가·장르·태그
- **회차 번호**: 제목 번호가 있으면 그 번호, 없으면 프롤로그를 뺀 등장 순서. 목록에 번호 칸 + 제목, 프롤로그는 "프롤로그", 후기는 "후기"

### 홈 · 소설 탭 · 칼럼 탭 (v2.6)
- **홈 이어 읽기**
  - 소설: 읽던 소설을 **최근 읽은 순으로 표지와 함께 가로 한 줄**. 누르면 읽던 위치로(그 회차를 다 읽었으면 다음 화 처음). 마지막 화까지 다 읽은 소설은 빠지고, 새 회차가 올라오면 "새 N"과 함께 다시 나옴
  - 칼럼: 읽는 중인 글을 최근 순으로 **최대 5개**(제목 · 분류 · 진행률)
  - "전체 ›" → 각 탭이 "읽는 중" 조건으로 열림
- **소설 탭**
  - 보기 전환(기기별 기억): **카드(기본)** / 작은 카드 / 리스트. 휴대폰 카드 2열·작은 카드 3열로 고정 (S25+ 에서 1열로 떨어지던 문제 해결)
  - 검색 한 칸: 제목 · 작가 · 장르 · 태그, 여러 단어는 모두 맞아야, `#단어`는 태그에서만
  - [필터] 창: 읽기 상태(전체/읽는 중/안 읽음/다 읽음/새 회차 있음) · 정렬(최근 읽은 순/최근 추가 순/제목 순/회차 많은 순) · 장르 · 태그(많으면 태그 찾기). 위에는 고른 조건만 칩으로
- **맨 위 · 맨 아래 바로 가기**: 소설 목록 · 회차 목록. 스크롤하면 나타났다 2초 뒤 사라짐, 회차 목록은 "읽던 회차" 버튼도
- **표지 크게 보기**: 소설 상세에서 표지를 누르면 화면에 맞춰 크게 (확대·축소 없음). 큰 표지(`cover_large_path`)가 있으면 그것, 없으면 목록용 표지 → 업로더 구현 사양: `docs/COVER_LARGE_SPEC.md`
- **칼럼 탭**: 분류 칩 줄 → **분류 선택 상자**. 읽기 상태와 정렬은 바깥 한 줄 그대로

- 받기: 소설 상세 [회차 받기] · 소설 목록 [여러 편 받기] · 카드 메뉴(길게 누르기 / PC ⋯: 회차 골라 받기 · 다음 50화 바로 받기) · 칼럼 목록·글의 받기
- 받기 창: 추천 버튼(전체 / 안 읽은 회차부터 / 다음 N화, 칼럼은 안 읽은 글 / 최근 N개) + 회차 하나씩 켜고 끄기, 다 읽은 것 빼기, 이번 달 남은 한도 막대
  - 한도를 넘게 고르면 "고르는 양을 줄여 주세요" + 받기 버튼 꺼짐, [용량 맞추기]: 전부 들어가는 것만 / ★ 먼저 + 이어 읽는 순서 / 골고루, 칼럼은 글만 받기
  - 기기에 이미 있는(열어 본) 회차는 0MB — 서버 전송 없이 옮겨 담음
- 확인: 모바일 데이터면 물어봄, 기기 공간 부족하면 막음, 한도를 다 썼으면 안내만
- 받는 중: 4개씩 동시에, 화면 켜짐 유지, 끊기면 다음에 "이어 받을까요?"
- 저장: Cache `seojae-content-dl`(개수 제한 없음) + IndexedDB `seojae-offline`. 로그아웃·차단 시 모두 지움. 이 브라우저(앱)에만 저장
- 서버 버전 비교(`content_hash`): 새 회차는 표시만, 바뀐 회차는 온라인에서 열면 자동 교체(한도 안 씀), 열지 않은 바뀐 회차·다시 나뉜 소설은 앱을 열 때 한도 안에서 자동으로 받음(모바일 데이터면 미룸), 서버에서 내려간 소설·칼럼·회차는 지움
- 오프라인: 연결이 바뀔 때 잠깐 알림 + 목록·홈·내 정보 맨 위 얇은 한 줄(스크롤하면 같이 올라감) + 읽기 화면은 위 바에 작은 "오프라인" 표시만. 받지 않은 글 흐리게, 30일 넘게 온라인 확인을 못 하면 받아 둔 글 잠금(연결되면 풀림)
- v2.8.1 속도: 오프라인이면 서버를 아예 부르지 않음(만료 토큰 갱신을 30초 기다리던 문제), 연결이 약하면 세션 3초·프로필 2.5초만 기다리고 마지막 값으로 먼저 열기, 회차·칼럼은 본문부터 그리고 서버 읽기 기록은 뒤에서, 서비스 워커 앱 화면 대기 4초 → 1.5초(오프라인이면 바로). 오프라인 + 만료 토큰으로 회차 열기 약 0.2초
- 다른 기기에서 더 읽은 위치: 글을 연 뒤 서버 기록에 이 기기가 쓰지 않은 더 새 기록이 있고 위치가 다르면 아래에 "다른 기기에서 「7화」 40%까지 읽었어요 [그 회차로]" (같은 회차면 [그 위치로], 12초 뒤 사라짐)

## 4. 소설 나누기 (inspect_novels.py · upload.py 공용)

### txt 판단 순서
1. `=====` / 제목 / `=====` 블록
2. **번호 줄기**: 여러 형식이 섞여도 번호가 이어지면 한 줄로 엮음
   - `N화 제목` · `N. 제목` · `N 제목` · `작품명 N화`(+다음 줄 제목) · `< 제목 >`+`#N` · `EP.N`
3. **빈 구간 채우기**: 번호가 빈 앞부분·중간·끝은 번호 없는 `< 제목 >`이나 **제목만 있는 줄**로 채움
   - 회차 크기가 고르게 되도록 고르고, 번호는 칸 수와 맞으면 그대로, 아니면 크기로 추정(`≈`)
   - 제목만 있는 줄은 본문에서 지우지 않음(잘못 골라도 글이 사라지지 않게)
   - 한두 화만 빈 곳은 앞뒤 제목과 닮은 줄만 씀
4. 엔딩 뒤 `후기`·`작가의 말` → 번호 없는 "후기" 회차
5. 그 밖: `< 제목 >`(충분히 촘촘할 때) → 제목만 있는 줄 → 5,000자 크기 분할(장면 전환 줄 우선, 상태창 상자 안은 피함)

같은 회차가 두 번 들어 있으면 하나만 남기고 경고합니다. inspect 표에는 `판정`(OK/✖ 보류)과 `혼합: 제목줄→N. 제목→…` 표시가 나옵니다.

보내 준 파일로 검증한 결과:

| 소설 | 예전 | 지금 |
|---|---|---|
| 당문전 | 41화 + 프롤로그 243만 자 | 1~484화 + 후기 (형식 5가지 혼합) |
| 약먹는 천재마법사 | 3화 + 프롤로그 944만 자 | 1~1474화 (작품명 N화 + 제목줄) |
| 사채왕의 천재손자 | 840화, 마지막 회차 140만 자 | 1~1060화 (꺾쇠+#N → N. 제목, 중복 3개 정리) |
| 시한부 천재가 살아남는 법 | 829화 | 829화 + 후기 (마침표로 끝나는 제목도 인식) |

### 원본 형태별 처리 (novel_sources.py)

| 형태 | 처리 | 키 |
|---|---|---|
| `작품.txt` | 위의 txt 나누기 그대로 | n / s / p |
| `작품.epub` | 목차(EPUB3 nav → 없으면 toc.ncx)의 맨 아래 단계 항목 = 회차. `#앵커`면 그 위치에서 자름. 목차 페이지·표지·짧은 권 표지 페이지는 버림. 목차가 회차 단위가 아니면(권 단위 등) 본문을 txt 처럼 나눔. DRM 이면 보류 | 번호 있으면 n, 없으면 s |
| `작품/0001화_제목.txt …` | 파일 하나 = 한 화. 순서·번호는 파일 이름 앞 번호. `◈ 075.`·끝의 `152화` 같은 중복 번호는 제목에서 뗌. `프롤로그.txt` 는 프롤로그. 본문 첫 줄이 제목·`N화` 이면 뺌 | n (같은 번호 파일이 둘이면 보류) |
| `작품/1권.txt, 2권.epub …` | 권마다 따로 나눈 뒤 이어 붙임. 표시는 `2권 · 12화 …`, 2권부터의 첫 회차 앞 내용은 "N권 앞부분" | `volume`: s + 권 2자리 + 순서 4자리 (s020012) |

- 폴더 판정: 이름에 `N권`이 절반 이상 → 권 / `N화`가 절반 이상 → 회차 파일 / 둘 다 아니면 파일 크기 중앙값 2만 자 이하면 회차 파일, 크면 권. epub 만 여러 개면 권
- 같은 작품 이름이 둘 이상(`작품.txt` 와 `작품/` 등)이면 둘 다 보류
- **짧은 회차**: 300자 미만이거나 중앙값의 1/5 미만 → 경고만 하고 올림, inspect·upload 끝에 목록 (다운로드 누락 의심). 다시 받아 넣으면 그 회차만 갱신
- 표지: 옆의 같은 이름 이미지 → (폴더) 안의 `cover.*`·`표지.*`·`폴더명.*` → (epub) 안의 표지 이미지
- EPUB 의 `dc:creator` 는 작가로 쓰지 않음 (다운로더 이름인 경우가 있음) → 작가는 `--meta` 로

샘플 검증: `하남자의 탑 공략법 본편.epub` → 1~327화(n 키), 중앙값 8,017자, **27화 441자 짧은 회차 경고**, 본문 첫 줄 중복 `1화`·`118화`·`140화` 제거

## 5. upload.py 사용법

```
python inspect_novels.py                 # 올리기 전 점검 (-v 회차 전체) — txt · epub · 폴더
python upload.py                         # 칼럼 + 소설 (바뀐 것만, 표지 포함)
python upload.py --dry-run               # 계획만
python upload.py --only novels
python upload.py --replace "이름.txt"    # 그 소설만 새로 올리기 (여러 번 지정 가능, --yes 질문 생략)
python upload.py --replace-all           # 보류 안 된 소설 전부 새로 ("모두 지움" 입력)
python upload.py --force "이름"          # 보류·순서 경고 무시 (이름 없이 = 전부)
python upload.py --split "이름=size:8000" # 회차 제목 무시, 글자 수로 나눔
python upload.py --delete "이름"         # 올라간 소설 통째로 지우기 (y 확인, --dry-run 미리 보기)
python upload.py --meta 소설정보.txt     # 업로드 뒤 작가·장르·키워드 반영
python upload.py --only meta --meta 소설정보.txt [--dry-run]   # 작가·장르·키워드만
```

- **보류**: 프롤로그 2만 자 이상, 회차 하나 3만 자 이상(중앙값 4배), 평균 2만 자 이상이면 올리지 않고 건너뜀. 끝에 건너뛴 소설과 소설별 해결 명령을 보여 줌
- **나누는 방식이 바뀐 소설**(예: sequence → number)은 `--force`로는 안 되고 `--replace`
- **다시 올려도 유지**: 소설 ID, 작가·장르·태그, 표지. 읽기 기록은 회차 키와 내용이 그대로인 회차만 남김
- **표지**: Pillow 필요(`pip install pillow`), 480×720 webp로 줄여 `novels/<id>/cover-<해시>.webp`. 이미지가 바뀌었을 때만 다시 올림
  - 큰 표지(크게 보기용 `cover-<해시>-l.webp`, 최대 1200×1800)는 업로더에 추가 예정 → `docs/COVER_LARGE_SPEC.md`
- 소설 구분은 **파일·폴더 이름** 기준 → 이름을 바꾸면 새 소설로 인식 (txt 를 폴더로 바꿀 때도 새 소설 → 기존 것은 `--delete`)
- **`--meta` 파일**: 빈 줄로 나눈 블록, 첫 줄 = 제목, `작가 :` `장르 :` `키워드 :` (쉼표·`/`로 나눔)
  - 적힌 항목만 덮어씀, `장르 :` 처럼 값을 비우면 그 항목을 지움. 웹 관리 화면과 같은 정리 규칙(태그 `#`·공백 제거, 중복 제거, `genre = genres[1]`)
  - 제목 찾기: ① 제목 그대로 ② 공백·기호 무시(제목·파일·폴더 이름) ③ 소설 제목이 블록 제목으로 시작하고 후보가 하나 (`하남자의 탑 공략법` → `… 본편`). 못 찾은 블록은 끝에 목록
  - `--dry-run` 이면 `장르: (없음) → 현대 판타지` 처럼 바뀔 내용만 보여 줌. migration_004 필요
- **소설 지우기**(`--delete`): 파일 이름(확장자·`novels/` 있어도 됨) · 제목 · ID로 지정, 여러 번 가능
  - 지우는 것: 소설 · 회차 목록 · 회차 파일 · 표지 · 작가·장르·태그 · **모든 사용자의 그 소설 읽기 기록**
  - 지우기 전 개수를 보여 주고 `y` 확인(`--yes` 생략), `--dry-run` 미리 보기. 이 명령은 삭제만 하고 끝남(업로드 안 함)
  - 폴더에 원본이 남아 있으면 다음 업로드 때 다시 올라가므로 빼 두라고 안내. `novels_map.json`의 ID는 남겨서 다시 올리면 같은 ID
